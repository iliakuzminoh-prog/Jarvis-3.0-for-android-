# JARVIS v4 — техническая башня

## Базовые условия

- Android-first, рассчитан на Redmi A5 и слабое железо.
- Без обязательного API-ключа для локальных возможностей.
- Никаких скрытых разрешений, рекламы, шпионажа или фоновой телеметрии.
- Разрешение запрашивается только тогда, когда пользователь запускает функцию, которой оно необходимо.
- Веб-поиск не является автоматическим fallback для обычного разговора.
- Код чужих проектов не копируется; используются только общие идеи и публичные Android API.
- Каждая новая возможность должна иметь отдельный исполнитель и тестируемый контракт.
- Нельзя считать количество строк мерой интеллекта.

## Архитектура

`UI -> Voice/Text Input -> Language Layer -> Intent Router -> Policy -> Executor -> Result -> Memory -> TTS/UI`

### Слои

1. **Input** — текст и Android SpeechRecognizer.
2. **Language** — нормализация русского/английского, формы слов и контекст.
3. **Intent** — определяет, что пользователь хочет сделать.
4. **Policy** — проверяет разрешения, подтверждение и границы действия.
5. **Executor** — выполняет ровно выбранное действие.
6. **Memory** — хранит пользовательские факты и контекст локально.
7. **Knowledge** — локальные справочники и учебные данные.
8. **Vision** — камера/изображения, только после явного запроса.
9. **Generation** — отдельный провайдер генерации изображений; не притворяется локальной нейросетью.
10. **UI** — независимый от логики красивый интерфейс.
11. **Diagnostics** — безопасные логи без содержимого приватных данных.

## Правило веб-поиска

Фраза вроде «что такое фотосинтез?» не должна превращаться в Google.

Фраза вроде «поищи в интернете новости про ...» должна создать SEARCH_WEB intent.

Фраза вроде «включи видео на YouTube про ...» должна создать YOUTUBE intent и передать запрос исполнителю YouTube. Она не должна запускать школьный справочник.

## Модель и память

Локальная память и локальная база знаний — это не то же самое, что обученная языковая модель.

Без вычислительного сервера нельзя честно заявлять, что APK содержит модель уровня облачного ChatGPT. Если появится 5 ГБ on-device model, её нужно рассматривать отдельно от кода и проверять, реально ли она работает на целевом устройстве по RAM, CPU/GPU, времени запуска и свободному месту.

### Tower 02 — исполнители
- AppExecutor
- BrowserExecutor
- YouTubeExecutor
- MediaExecutor

### Tower 03 — язык
- русская морфология и варианты команд
- английские варианты

- контекст диалога

- школьные справочники

- физика/химия/биология

### Tower 05 — vision
- выбор изображения
- камера по запросу
- распознавание
- описание

### Tower 06 — генерация
- абстракция ImageGenerator

### Tower 07 — интерфейс
- 3D/световой orb
- состояния listening/thinking/executing/speaking
- история диалога
- карточки действий

### Tower 08 — тестирование
- unit tests для языка и роутера
- permission tests
- executor tests
- regression suite
- Android lint
- APK build
- проверка подписи и SHA-256

## Контроль качества

Нельзя объявлять APK готовым по факту успешной компиляции.

Готовность означает:
1. compile проходит;
2. lint проходит;
3. APK существует;
4. подпись проверяется;
5. ключевые intents проходят тесты;
6. опасные/чувствительные действия не выполняются без нужного разрешения;
7. веб-поиск не срабатывает самопроизвольно;
8. память действительно сохраняется и удаляется;
9. после ошибки executor не сообщает об успешном действии.
